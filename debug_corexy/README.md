### ★ 全广播寻址（2026-09-30 定调：一条线一台，不需要 ID）

一条 UART 只挂一台驱动器，所以**运动/停止/使能全部用广播地址 0x00**——与产品
`zdt_motor.c` 完全同口径（产品三台也是全广播），**不需要知道、也不需要配置驱动器 ID**。
上电自检只做一件事：三条线各发一帧广播使能（把电机拉进使能态）：

```
[BOOT] 寻址 = 全广播 0x00（一条线一台，与产品同口径）；三条线已广播使能
       （本批驱动器对广播不回包，无 [ACK] 属正常）
[BOOT] 想验驱动器会不会说话：`scan`（单播逐 ID 探测，对自己的 ID 会回 02）；运动流程不依赖应答
```

- ★ **本批驱动器对广播不回包**（实测：ID 非 1 时广播帧无应答）——所以运动路径**只发不收**，
  与产品"只发不收"一致；`ack`/`scan`/`send`/`j <数字地址>` 保留为**单播诊断工具**。
- `id a/b/t <地址>` 仅影响单播诊断帧的匹配；`id x 0` 回到广播。运动一律广播。
- **A/B 谁在左谁在右由装机决定**：`x 30` 方向反了改产品 `CFG_AXIS_A/B_SIGN`（README §4 符号表）。

### ★★ 2026-09-24 台架实测（当天全部结论，先看这一节）

**总线侧：**
| 事实 | 证据 |
|---|---|
| 三台驱动器实际地址是 **1 / 2 / 3**；其中 **只有 3 号（和当时接上的 2 号）会应答** | `scan 8` → `02 f3 02 6b`、`03 f3 02 6b` |
| 驱动器**会回应答**：`[地址][功能码][02][6B]` = 命令已正确接收 | 同上；`02` 出现即链路通 |
| 出错时的回包：`[地址][00][EE][6B]` = 校验/帧被拒，`[地址][00][E2][6B]` = 参数越界 | `j 2` 实测到 `02 00 ee 6b` |
| **只接受控制类指令、拒绝运动类指令（F3/FE/93 收，FD/F6 回 EE）= 该驱动器控制模式是"脉冲+方向"** | 对 2 号逐条试出来的；这种模式下它照样应答、照样上电锁轴，但不执行串口运动指令 |
| 波特率全部 115200（9600/19200/38400/57600/230400 无人应答） | 逐档 `ack 1/2/3` |

**固件侧：三个把板子搞成"看着死机"的 bug（都已修，都是通用教训）**
1. `USART1_IRQHandler` 曾是**空函数**而总线接收中断被打开 → 标志不清、中断无限重进、CPU 100% 卡死、SysTick 饿死。教训：**开了接收中断就必须在 ISR 里读 SR+DR**。
2. `TICK_INT_PRIORITY = 15`（SysTick 最低）+ UART 中断优先级 5 → 中断一多 `HAL_GetTick()` 冻结，所有"带超时"的循环退化成死循环（横幅打半句就停）。教训：**tick 的优先级必须高于外设**。
3. `__HAL_UART_ENABLE_IT(&huart, UART_IT_RXNE | UART_IT_ERR)`：HAL 的 `UART_IT_x` 是"寄存器号<<28 | 位"的编码，**用 `|` 拼两个会破坏编码**（`0x30000021` 被当 CR3 位）→ `RXNEIE` 根本没打开，控制台"只出不进"。教训：**中断使能逐条写，或直接写 CR1/CR3 位**。

**排查手法（这次靠它们定位，值得留着）**
- `pyocd`（装一次即可）读 MCU 现场：`halt` + `reg pc` + `read32 0xE000ED04`(ICSR) / `0xE000ED28`(CFSR) / `0xE000E304`(NVIC active) + 外设寄存器 → 一次就能分清"卡在中断里 / 硬件异常 / 主循环正常"。
- **PA1 线路体检**（`[PROBE]` 行）：把 RX 脚当输入采样，量 PC 发字节时有没有边沿 → 分清"字节没到引脚"还是"MCU 没收到"。
- 驱动器**自己就是裁判**：拿 `send` 把候选帧发进去，读回包（`02` 接受 / `EE` 校验拒 / `E2` 参数拒），比翻手册快。

### ★ 关于波特率 9600（容易记混的一处）

**步进总线是 115200，不是 9600** —— 三个独立来源都这么写（下表是「物创1」板时期的证据，
2026-09-30 换产品板后电机线是 USART3/UART5，波特率口径不变）：

| 来源 | 步进总线（当时=USART1 PB6/PB7） | 蓝牙座（UART4 PA0/PA1） |
|---|---|---|
| 物创 `DEBUG_GUIDE.md` §1.2 串口表 | **115200 8N1，校验 0x6B** | **9600 8N1**（JYD24M 蓝牙模块） |
| 物创固件 `Core/Src/usart.c` | 115200 | 115200 |
| `D:\CUBEMX DOCUMENT\motor test`（`Core/Src/usart.c` + `.ioc`） | **115200** | 115200 |

`9600` 在这个工作区里只出现在**蓝牙座那一行**（`JYD24M 蓝牙 9600 8N1`）——而蓝牙座正是本工程控制台用的 **UART4/PA0/PA1**。
所以"9600"是**控制台那个口**的印象，不是电机总线。本工程控制台按 USB-TTL 用 **115200**（你在串口助手里设的就是它）。

⚠️ 但**驱动器自己的波特率是驱动器侧的参数**（可以在驱动器的按键菜单或厂商上位机里改），
所以若 115200 下发帧毫无反应，还是值得逐档试一遍 —— 现在有回包探测，试起来很快：
`baud 9600` → `ack`（有回包/抱死就是这一档）→ 不行再 `baud 57600` / `38400` / `19200` / `230400`。

**与产品 `code/` 的关系（2026-09-30 起）**：
1. **接线完全一致**：A=USART3(M1)、B=UART5(M2)、舵机 PB9/PB8、控制台 UART4(CN1)、限位 PB1/PC5/PB0。
2. 位置帧字节数、字段完全一致（**13 字节**，`[ID][FD][dir][spH][spL][accel][pulse4B][md][sync][6B]`）。
3. 差别只剩架构：产品是 FreeRTOS 四层 + 守护任务；本工程是裸机超循环 + 命令台，方便逐段验证流程。

**接线三步**：
1. 调试探针接产品板 SWD（烧录），它的 CDC 串口桥接 CN1（UART4：模块 RX ← 板 PA0、模块 TX → 板 PA1、共地，115200-8-N-1）；
2. 电机 A 接 M1 座（USART3）、电机 B 接 M2 座（UART5），TX↔RX 交叉、与主控共地；
3. 12V 给 42 电机（**先只接一台**），手放电源开关上。

## 2. 怎么跑

```bat
:: 编译：0 Error / 0 Warning
"D:\Keil v5\UV4\UV4.exe" -r "D:\CUBEMX DOCUMENT\工创\debug_corexy\MDK-ARM\debug_corexy.uvprojx" -j0 -o build.log
:: 或双击 uvprojx → Build → DAPLink 下载
```
上电后控制台立刻打出配置、待核实清单与提示；**3 秒内不敲任何键就自动跑全回零 `home`**
（homex→homey→thome，与产品上电自动归零同款；3 秒内任意键 = 本次跳过，之后想归零随时敲 `home`）。
烧录/换线等不想让电机自己动的场合：上电 3s 内发一个回车即可（`DBG_CFG_AUTO_HOME_ON_BOOT` 可永久关）。

**PC 端就用普通串口助手**（XCOM / SSCOM / 友善串口助手都行），不需要任何自写上位机：

| 项 | 设成 |
|---|---|
| 端口 | USB-TTL 所在的 COM 口 |
| 波特率 | **115200**，8 数据位 / 1 停止位 / 无校验 / 无流控 |
| 字符编码 | **UTF-8**——横幅有中文，GBK/ANSI 助手会把中文显示成乱码（2026-09-25 实测）。助手没有编码选项就用 `Tools/console.py` |
| 发送新行 | 勾上（`\r\n`、只 `\r`、只 `\n` 固件都认，见 `dbg_console.c`） |
| 本地回显 | 可开可不开：固件**不做逐字符回显**，但每收到一整行会打 `> 原样`，总能核对你发的内容 |
| 十六进制显示 | 关掉（固件只输出 ASCII） |

上电应立即看到 `[CFG] ...` 与 `[HELP] ...` 两段。**没看到就是这三件事**：USB-TTL 的 RX 是否接到板子 PA0（TX↔RX 必须交叉）、有没有共地、波特率是不是 115200。

**上手顺序建议**：
```
en all                    # 使能两台
j a cw 30 320             # 单台小角度点动：电机会不会转？（不转先查 ID 与 12V）
scan                      # ID 不确定时：两条线逐 ID 发使能，应答的就是那个 ID
x 50                      # 按 X 意图走 50mm：应整体向右平移，A/B 同向同量
y 50                      # 按 Y 意图：应整体向下，A/B 反向同量
sq 50                     # 方块四段，走完应回到起点附近
cal 100                   # 标定距离：走 100mm，卷尺量 D → 新 ppm = 100×ppm/D
raw claw 1600             # 夹爪扫行程（如 1200→2000 一点点试），找不打架的两端（扫行程用的起始探针值，不是档位）
g 0 / g 1 / g 2           # 夹爪档位，**顺序 = 命令表的 0开/1紧/2初夹**（全开 1250 / 兜底夹紧 1950 / 兜底初夹 1750）
l 0 / l 1                 # 升降 抬升/下伸
stop                      # 任意时刻立即停双轴
```

## 3. 命令表

| 命令 | 参数 | 作用 |
|---|---|---|
| `help` | — | 命令表 |
| `cfg` | — | 打印配置（含待核实项） |
| `stat` | — | 状态：舵机当前脉宽、限位三路电平、上次运动的估算/实测 |

| `stoptest` | — | ★停止帧台架实测：广播走 10mm@3mm/s，600ms 后运动中发停止三连，逐帧判决现场打印（挪的 ~2mm 不进位置记账） |

| `sq` | `<mm> [mm/s]` | 方块测试 X+ Y+ X− Y− |
| `p` | `<X> <Y> [mm/s]` | ★**绝对定位**：目标坐标走过去。**第三象限约定：原点=归零驻留位（触发点内退 3mm）**。**软限位（2026-10-01 更新：X 下限 −122→**−135** = 龙门可达极限）：X ∈ [−135, 0]、Y ∈ [−187, 0]**——Y 下限就是投放点；越界拒绝。先 `homex`+`homey` 才可用；撞限位/手动 stop 会作废记账。`p` 不带参数=打印当前位置 |

| `homey` | `[mm/s]` | ★Y 轴回零（**两相**，2026-09-30 简化）：向最大端(Y+)粗压**撞开关即停** → 退 `DBG_CFG_HOME_BACKOFF_MM`（默认 **3mm**，脱不开自动加倍退一次）→ 电平复核；假沿作废、两次尝试；任意键=软急停 |
| `homex` | `[mm/s]` | ★X 轴回零（两相，同 `homey`；X 限位 PB1） |
| `thome` | `[粗寻标rpm]` | ★转盘回零（五相）：凸块退出→粗寻标→反向脱开（**没脱开自动加退，最多 4×600 脉冲**）→慢压定零→**正向偏移 10° 对格**（`DBG_CFG_TRAY_HOME_OFFSET_DEG`（10°）：凸块零位与格中心的装配偏差；驻留位在开关外不压开关）。走通 = 原点开关 PB0 校准正确；任意键=软急停；两次尝试 |

| `sstop` | `<claw\|lift>` | 停该路舵机 PWM（顶死/发烫时的第一反应；再发档位命令会自动重起） |
| `scan` | `[最大ID]` | A/B/T 三条线各自逐 ID 试使能 + 收回包，找驱动器的实际地址 |

| `send` | `[a\|b] <两位十六进制字节...>` | ★把任意字节原样发到指定线（缺省 A 线）并打回包（`dump` 会给出整行） |
| `spu` | `[1\|10]` | ★速度字段系数：1 = 字段即 RPM（产品口径），10 = 字段是 0.1RPM（物创口径） |
| `dump` | `[地址] [脉冲]` | ★把使能帧/位置帧的**字节**打出来（不发）+ 可直接粘贴的 `send` 行 |
| `loop` | `[次数]` | ★TX/RX 回环自检：短接某线的 TX/RX 后跑，A/B/T 三线各测一遍，证明 MCU 发送链路没问题 |
| `baud` | `[bps]` | ★改三条电机线波特率（9600/19200/38400/57600/115200/230400），驱动器被别人改过波特率时用 |
| `fmt` | `<13\|16>` | ★位置帧格式：13 = 老协议（脉冲/RPM，实机用这个），16 = X57_V2 说明书协议（0.1°/0.1RPM，实机不适用，仅对照用） |
| `lim` | `[clr]` | ★限位/原点开关：三路电平 + 消抖后沿计数（40ms 门限=按压次数；`lim clr` 清零）。接线：X=PB1 / Y=PC5 / 转盘原点=PB0，COM→GND、NO→信号；产品 PCB 已带 4.7k 外部上拉 |
| `k230` | `[clr\|live [秒]\|sim <类> <x> <y> [形状]]` | ★**视觉链路**（解析器=产品源码副本）：`k230` 快照（最近帧/类别+形状/换算后机械坐标/收帧计数/原点符号配置）；`live 10` 实时流（任意键停）；`sim 3 60 45 2` 本地注帧（不接线验解析→换算；形状缺省 0=默认方案，给 4+ 可验越界路径；注：sim 注帧也算"链路活性"，验完想看真实链路先 `k230 clr`）；`clr` 清缓存 |
| `read` | `[等待s]` | ★**到读帧位再取目标**（产品读帧纪律的台架版）：goto 投放点上方+静默 500ms+清缓存+等新鲜帧，打印类别+形状/视觉/机械坐标和可照抄的 `pick X Y 100 <形状>`。**作为抓取依据的坐标必须出自它**——归零/待机位正压托盘挡相机，`k230` 快照随时可看但不作数 |
| `scr` | `<控件名> <数值>` | ★**屏**：发 `控件名.val=数值+FFFFFF`（如 `scr n1 5`）。没反应先查屏端波特率是不是 115200 |
| `scrp` | `<控件名> <图片号>` | ★屏：发 `控件名.pic=图片号`（整图切换） |
| `scrt` | `<控件名> <文本...>` | ★屏：发 `控件名.txt="文本"` |
| `scrtest` | `[0]` | ★**屏自检**：n1~n6 写 1~6——屏上"成功数量"列自上而下亮 1,2,3,4,5,6 = 控件名/行序/链路全对；**某行不动 = 该控件名在屏工程里不存在**（静默失败）。`scrtest 0` 全部清零 |

## 4. 示波器观测变量（Keil Watch / Logic Analyzer 画曲线用）

一组全局独立标量（`dbg_app.h` 有清单），主循环每圈刷新：
`g_scope_tick`（圈数，一直爬=固件活着）、`g_claw_us`/`g_lift_us`（舵机脉宽）、
`g_lim_x`/`g_lim_y`/`g_lim_tray`（限位原始电平）、`g_lim_x_cnt`/`g_lim_y_cnt`/`g_lim_tray_cnt`（**按压计数**：消抖+状态闩锁，只认压下方向，一个按压循环恒 +1，松开弹跳不计）、`g_move_est_ms`/`g_move_act_ms`。

- **Watch**：调试会话 → `View → Watch Windows → Watch 1` → 输入 `g_lim_y` 等名字；
  ⚠️ **必须勾 `View → Periodic Window Update`**，程序跑着时窗口才刷新
- **Logic Analyzer**：`View → Logic Analyzer` → Setup → New → 填同样的名字（按一次开关，`g_lim_y` 打出 1→0→1 脉冲、`g_lim_y_cnt` 台阶 +1）
- ⚠️ 变量必须是**单个名字**：结构体成员路径（`g_scope.lim_y`）在 LA 里 cannot evaluate——所以这组量特意做成独立标量
- ⚠️ SEGGER J-Scope 只认 J-Link 硬件，本台架的 Horco 探针用不了

`x/y/xy/sq` 走的是**产品自己的 `Kinematics_XYSolve`**（本工程 `User/Algorithm/` 里是产品源码原样副本）——
所以这些命令量到的方向、距离、耗时就是对**产品算法**的直接检验，不是另一套实现。

### ★ 驱动器回包（ACK）：电机不动时先看这个

ZDT 驱动器收到**正确**的命令会立刻回一帧，这也是"链路通不通"最硬的证据
（来源：物创 `code/ZDT_drive.c` 的 `receive_enable/speed/angle_*` 应答表，那边是用 2ms 超时收的）：

| 回包 | 含义 |
|---|---|
| `[地址][功能码][02][6B]` | 命令已正确接收 → **帧确实进到驱动器里了**，问题不在 MCU 这一侧 |
| `[地址][00][EE][6B]` | 校验错误（帧长/校验字节不对） |
| `[地址][00][E2][6B]` | 参数错误（转速/加速度/脉冲越界） |
| 什么都没回 | 这一帧没有任何驱动器收到：供电 / 接线 / 波特率 / 地址 / 控制模式 |

上电自检 = 三条线各一帧**广播使能**（只使能，不含运动指令，电机不会走）。
★ 广播帧**没有回包是本批驱动器的实测特性**，不是故障——要看"驱动器会不会说话"用
`scan` / `ack <数字地址>`（单播，对自己的 ID 回 02）。运动流程不读应答。

```
ack 1       # 只对地址 1 探测（只发使能帧）
ack all     # 对配置的 A、B 两个地址各探一次
scan 8      # 1~8 逐个探：有回包的那个 ID 就是这台驱动器的地址（不用再靠手拧了）
```

⚠️ 个别固件的应答功能可以被关掉，所以**"没回包"不等于"链路一定断"**；两种证据一起看：
回包看的是"帧到没到驱动器"，`en 0` 之后手拧看的是"驱动器有没有真的动起来"。

### ★ 速度字段的单位到底是 RPM 还是 0.1RPM（差 10 倍）

产品与物创两条口径不一致，而且**两边都没上真机核过**：

| 来源 | 口径 | 依据 |
|---|---|---|
| 产品 `code/`（本工程默认） | 帧内数值 = **RPM** | `Kin_RpmForSpeed()` 算出 rpm 直接进帧 |
| 物创固件 | 帧内数值 = **0.1RPM** | `config_robot.h` 该节标题写「运动速度 (0.1RPM)」，且它的时间公式 `z_time_s = 0.1mm数 × 30 ÷ 字段值` 只有按这个口径才自洽 |

用秒表定：`j a cw 30 3200`（**正好一圈**，不做系数换算）

- 实测 ≈ **2 s** → 字段就是 RPM，产品口径对，`spu 1`（默认）
- 实测 ≈ **20 s** → 字段是 0.1RPM，**产品会整体慢 10 倍、所有时间估算差 10 倍**，这是要写进待办的发现

`spu 10` 把"意图路径"（`bx/x/y/xy/sq/cal`）一起切到 0.1RPM 口径；`j` 永远发你给的原始数值。

### 不知道驱动器 ID 时：先用广播（地址 `0x00`）

ZDT 协议里地址字节写 `0x00` = 该线上的驱动器都响应。命令台里地址写 `0` 或 `bc` 就是广播
（两条线各发一遍，应答各回各的线，都能读到）：

```
en 0        # 广播使能：发完手拧两台，都抱死 = 广播对这两台有效
bx 50       # 广播走 X：两台同向同量 → 龙门整体平移 50mm（不需要知道 ID）
bx -50      # 反方向
j 0 cw 30 3200   # 广播原始点动（脉冲口径，3200 脉冲 ≈ 40mm 皮带行程）
dis 0       # 广播失能
stop        # 停止 = A/B/T 三线各发一帧广播停（2026-09-30 起不读应答）
```

⚠️ **广播的固有限制**：一帧只能给所有台**同样的方向 + 同样的脉冲数**，换算到 CoreXY 就是
"两台同向同量 = **纯 X 平移**"。所以广播能做的只有：让两台一起动、验 X 方向、大范围移动。
**纯 Y（要两台反向）、方块闭合、耦合验证、按意图走任意 X/Y —— 都必须知道各自的 ID。**
（ID 用 `scan` 核出来；全广播定调后运动不依赖地址，`id a/b/t <地址>` 可运行时改登记地址。）

⚠️ 若两台驱动器**本来就是同一个 ID**（出厂默认常见都是 1）：`scan` 会看到"每个 ID 试时两台一起抱死"，
而且此时**按地址发也是两台一起动**——想分开控制就得先把其中一台改成别的 ID
（用张大头官方上位机，或手册里的改地址指令；本工程**不预置那个帧**，避免猜帧格式出错）。

**方向判据**：纯 X 走 → A/B **同向同量**；纯 Y 走 → A/B **反向同量**。不一致就是耦合/接线问题。
方向修正规则（重要，别乱试）：
| 现象 | 改法 |
|---|---|
| X 对、Y 对、方块闭合 | 不用改 |
| 两个方向都反（X+ 向左且 Y+ 向上） | `CFG_AXIS_A_SIGN` 与 `CFG_AXIS_B_SIGN` **同时取反** |
| X+ 变成沿 Y 走 | 两轴对调：**只取反其中一个**（先试 A） |
| 单一轴反（X 对 Y 反） | **两个符号无解**，是接线/装配不对称，要动硬件（对调一台的一对线圈） |

## 7. 目录与约定

```

Core/                    裸机：main（超循环）/usart（6 路）/tim/it/msp
User/Algorithm/          motion_kinematics —— 产品源码原样副本（被检验的算法）
```
