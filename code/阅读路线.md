## 1. 地图：五个目录各管什么（20 分钟）

| 层 | 目录 | 职责 | 顺序 |
|---|---|---|---|
| 常量 | `Config/sort_config.h` | **所有可调数字的唯一住所**：脉冲换算、速度、超时、串口语义编号、引脚 | 1 |
| 设备 | `User/Devices/` | 把字节翻译成设备动作：`zdt_motor`（电机帧）`servo`（舵机档位）`k230_uart`（视觉帧解析）`tjc_screen`（屏指令） | 2 |
| 板级 | `User/Bsp/` | 接到底层：`bsp_uart`（6 路环形缓冲）`bsp_gpio`（限位电平 + EXTI 事件锁存） | 3 |
| 算法 | `User/Algorithm/` | 纯数学：CoreXY 解算、时间估算、转盘整圈数——不碰硬件、不碰 RTOS | 4 |
| 应用 | `User/App/` | 三个业务任务 + 一个守护任务，业务逻辑全在这 | 5 |

依赖**单向**：`App → Devices → Bsp`（Algorithm 独立）。读到"下层 include 上层"就是 bug。
`sort_config.h` 开头六行是**硬件映射的唯一真源**（原理图 2026-09-14 版），先读那六行。

## 2. 主干：跟着一件货走一遍（60 分钟，最重要的一步）

## 3. 三个最容易读错的地方（20 分钟）

1. **电机只发不收**：`zdt_motor.c` 里没有任何接收代码，`bsp_uart.c` 的 RX 只是吞总线噪声。
   所以"到位"＝时间估算（`Kinematics_MoveTimeMs`），唯一的物理反馈是开关沿。**别去找"读电机位置"的代码——它不存在，这是设计选择。**
2. **转盘索引沿的能力边界**：一圈只有一个沿 ⇒ 只能给"绝对基准 + 每笔整圈数核对"，不能连续测角度，一圈之内的丢步检不出。
3. **`bsp_uart.c` 的 `s_huart[]`**：它是"语义编号 → 句柄"的表，**不是按外设编号直排**（2026-09-14 改版踩过：编译和仿真全过，现场却是"屏不刷新 + 转盘不动"）。改线前先读它与 `sort_config.h` 顶部六行，**必须逐行同序**。

| 打滑的检出边界 | `make s6` | 只有跨整圈的那一笔能检出（故意 FAIL） |

## 5. 动手改代码前的五条纪律

1. **改硬件映射要同时改 6 处**（`sort_config.h` / `usart.c` / `hal_msp.c` / `gpio.c` / `.ioc` / `bsp_uart.c` 的 `s_huart[]`），改完 `sort_config.h` 末尾的编译期断言会替你挡一道。
2. **引脚/极性判断不能写成 `#if`**（HAL 的 `GPIO_PIN_n` 带强制转换、`GPIO_PIN_RESET` 是枚举量），要用 `SORT_CFG_ASSERT` 那种编译期断言——否则真机炸、仿真过。
3. **改完必须 `make run`**：基线见 `../仿真审计结论.md`（唯一 FAIL = 刻意保留的 s6）。多一个 FAIL 就是回归，别调判据去凑。
4. **改电机帧要对着 Emm_V5.0 手册**，不能对着本工程的文档或参考实现——位置帧 12/13 字节这个错，文档、代码、仿真模型曾一起错了三轮。
5. 提交前跑 `clang-format -i Config/*.h User/*/*/*.c User/*/*/*.h`（`Core/` 除外）。
